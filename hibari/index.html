Open Source // LLM Engine Built From Scratch

Hibari

An LLM engine written from first principles in PyTorch — and Koto, the conversational model built with it

Every part of Hibari is written directly: the Transformer, the byte-level BPE tokenizer, the training loop, KV-cache inference, a safety layer, a reply critic and a native GGUF exporter. No pretrained weights and no high-level model library are used. Its first model, Koto, lives in its own repository as a Git submodule of Hibari; the current release is Hibari-Koto1.3.1:29M.

What Hibari is

The engine and its name

Hibari (雲雀, Japanese for the skylark) is a research project to build a language model the long way: every layer is written and tested in this repository instead of being imported. The goal is understanding — a small model whose every number can be traced to the code, data and run that produced it.

The engine is deliberately model-agnostic: sizes come from a config file, and a model lives in its own repository. Koto is the first one; a release binds its checkpoint, tokenizer and GGUF files together by SHA-256, so a published file can always be traced back to its training run.

Architecture

How a reply is produced

Inside the engine

One package per responsibility
LayerPackageWhat it does
Modelhibari.modelDecoder-only Transformer: token embedding, RoPE, multi-head causal attention with KV cache, SwiGLU, pre-RMSNorm, tied output head, residual dropout
Tokenizerhibari.data.tokenizerByte-level BPE (4,096 tokens), chat template, escaping of special-token text typed by users
Datahibari.dataConversation formatting, windowing that never cuts a reply, assistant-only loss masking, length-grouped batching
Traininghibari.trainingAdamW with warm-up + cosine schedule, token-weighted gradient accumulation, resume, checkpoint provenance
Inferencehibari.inferenceBatched KV-cache sampling, streaming, chat session with context trimming, rewriting-task router, informal-text normalisation
Safety & rankingsafety · rerankingDeterministic safety layer with reviewed responses; a critic that ranks several model-written replies (it never writes text)
Exporthibari.exportNative GGUF writer (F32 / F16, then Q8_0 / Q4_K_M via llama.cpp) and a NumPy reference runtime that reads only the GGUF
Releasehibari.releaseRelease profiles that bind version, weights, tokenizer and GGUFs by SHA-256; validator; generated Ollama Modelfile
